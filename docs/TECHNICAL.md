# 技術資料: Video Converter for X

## 目的
いろいろな形式の動画を、X（旧 Twitter）に投稿して再生できる形式に変換する Windows 用アプリ。

## 名前
- アプリ名は **Video Converter for X**（公開前の 2026-11-14 に「Twitter Video Converter」から変更）。
- exe・配布フォルダ・zip は `VideoConverterForX`（`VideoConverterForX.exe`、`VideoConverterForX-<版>.zip`）、設定の保存先は `%APPDATA%\VideoConverterForX`。
- 変換したファイルの名前の末尾は `_x`（`元の名前_x.mp4`、分割時 `_x_01.mp4`、編集時 `_edit_x.mp4`）。

## 構成
- Python 3.12 + tkinter（画面）+ tkinterdnd2（ドラッグ＆ドロップ）+ ffmpeg（変換。imageio-ffmpeg の exe を同梱）。
- PyInstaller（onedir）で exe 化。配布物は `files/VideoConverterForX-<版>.zip`。
- `src/xvideo/core.py` … 変換の中身（情報の読み取り・大きさ/fps/区間の計画・ffmpeg の実行・結果の確認）
- `src/xvideo/gui.py` … 画面。`src/app.py` が入口
- `src/xvideo/cli.py` … コマンドライン版（`python -m xvideo.cli 入力.mp4`）
- `tests/run_tests.py` … テスト動画を ffmpeg で作り、変換結果を確かめる。`tests/gui_test.py` … 画面を自動で動かす
- `tests/edit_test.py` … 切り貼り・フェードの変換とプレビュー。`tests/editor_test.py` … 編集の窓を自動で動かす
- `tests/make_screenshots.py` … README 用の画面の画像（テスト用の動画だけを写し、保存先は「元の動画と同じフォルダ」表示）を `release/screenshots/` に作る
- 公開用: `LICENSE`（MIT (c) 2026 BW）、`THIRD_PARTY_NOTICES.md` + `licenses/`、`requirements.txt`。
  `make_release.py` が GitHub に置く一式を `release/` に作る（ソース・テスト・README・ライセンス・技術資料 `docs/TECHNICAL.md` = この仕様書の作業メモの言い回しを直したもの・.gitignore）。
  最後に個人情報（PC のユーザー名・ホームのパス・メールアドレス・作業フォルダ名・チーム内の呼び名）が入っていないか調べ、見つかれば止まる。
  exe の zip にも README・LICENSE・THIRD_PARTY_NOTICES・licenses・screenshots を同梱する。
- 画面の見た目（テーマ・一覧の行の高さ）は `gui.setup_style()` にまとめ、アプリ本体・テスト・スクリーンショット作りで共通に使う。

## X の投稿条件（core.py の先頭の定数。2026-11 時点の理解。公式の条件が変わったらここを直す）
| 項目 | 通常アカウント | Premium |
|---|---|---|
| 長さ | 140秒（2分20秒） | 約4時間 |
| 容量 | 512MB | 16GB |
| 大きさ | 1920x1200 以内（縦長は 1200x1920 以内） | 同じ |
| 縦横比 | 1:3 〜 3:1 | 同じ |
| コマ数 | 60fps 以内 | 同じ |
| 形式 | MP4、H.264（High）、yuv420p、AAC-LC、正方形の画素、プログレッシブ | 同じ |

※ この表は作成時点（2026-11）の作者の理解によるもので、公式ページでの再確認はしていない。投稿に失敗する報告があれば公式ヘルプを確認して直す。

## 出力
- `元の名前_x.mp4`（分割時は `_x_01.mp4` …）。元と同じフォルダ、または指定のフォルダ。既にあれば上書き。
- 映像: libx264、preset medium、High プロファイル、yuv420p、CRF + maxrate（VBV）、キーフレーム間隔 2秒、固定フレームレート。
- 音声: AAC-LC 160kbps、48kHz、ステレオ。音声がない入力には無音（anullsrc）を入れる。
- `-movflags +faststart`、メタデータ・字幕・チャプターは外す。
- 画質の設定（CRF / 映像の最大ビットレート）: 高画質 18 / 12Mbps、標準 21 / 8Mbps、軽い 25 / 4Mbps。

## 変換の決まり
- 大きさ: 見た目の大きさ（回転と画素の縦横比を反映）を、上限の枠（設定が 720p のときは 1280x800 / 800x1280）に収まるよう縮小。拡大はしない。幅・高さは偶数。
- 縦横比が 3:1 を超えるときは黒い余白（pad）を足す。
- fps: 元の fps と上限（60 または 30）の小さい方。23.976 / 29.97 / 59.94 は分数で指定。fps フィルターで固定フレームレートに。
- HDR（smpte2084 / arib-std-b67）: zscale + tonemap（hable）で BT.709 の SDR に。
- インターレース: `yadif=deint=interlaced`（印の付いたコマだけ）。
- 長い動画（通常アカウントで 140秒超）: 分割（139秒ごと。上限ぴったりを避けて 1秒余裕）／最初の 139秒だけ／そのまま（結果に注意を表示）。
- 使う範囲（開始・終了）を指定できる。分割はその範囲の中で行う。
- 容量: 区間の長さから上限の 95% に収まる最大ビットレートを計算。それでも超えたらビットレートを下げて最大3回やり直す。150kbps を下回るなら失敗にする。
- 変換後に出力を読み直し、大きさ・縦横比・fps・容量・長さを確認して、問題があれば「注意」として表示。
- 書き出しは `.part.mp4` に行い、成功したら名前を変える。中止・失敗時は消す。

## 画面
- 一覧（ファイル・長さ・元の大きさ・状態）。ドラッグ＆ドロップ（ファイル・フォルダ）、exe のアイコンへのドロップにも対応。
- 設定: アカウントの種類、長い動画の扱い、画質、大きさ、なめらかさ（fps）、使う範囲、保存先。
- 設定は `%APPDATA%\VideoConverterForX\settings.json` に保存（使う範囲は保存しない）。保存先がまだなく、改名前の `%APPDATA%\TwitterVideoConverter\settings.json` があればそれを読む（保存は新しい場所へ）。
- 進み具合のバー、中止、保存先を開く、このアプリについて（非公式である旨・商標・権利のある動画だけを扱う旨・著作権表示を含む）。

## 公開物の文言の方針（2026-11-13、公開前の推敲）
- 「X に投稿できる形式」ではなく「X の投稿条件に合わせた形式」と書く（投稿できることを保証しない）。
- 非公式である旨・X Corp. と無関係で承認や提携もない旨・商標の表示を README の冒頭・注意・THIRD_PARTY_NOTICES・LICENSE の末尾・「このアプリについて」に入れる。
- 権利のある動画だけを変換・投稿すること、X の利用規約を守ることを README の注意に書く。
- README に「動作確認の範囲」を置き、確認したこと・していないことを分けて書く。
- 画面の画像には第三者の映像を写さない（テスト用の色の帯の映像だけ）。X の画面・ロゴも使わない。

## 編集（1.1.0 で追加）
- `src/xvideo/edit.py` … 編集のデータと変換・プレビュー用のコマンド作り。`src/xvideo/editor.py` … 編集の窓。
- データ: `Project` = `Clip`（元の動画・開始秒・終了秒）を順に並べたもの + 全体のフェードイン秒・フェードアウト秒（各 0〜10秒、全体の半分まで）。
- 操作: 分ける（split）、部分を消す（delete）、前/後ろを消す（keep_range）、順番の入れ替え（move）、別の動画を足す（append）、元に戻す（50回まで）。0.1秒より短い部分は作らない。
- 一覧の1行 = 出力1本。編集した行は `project` を持ち、名前の前に ✂ が付く。複数の行を選んで編集を開くと、つなげて1行にまとまる。何も変えずに「決定」したら編集なしに戻る。
- 変換: `build_graph` が、クリップごとに `-ss/-t` 付きの入力 → 大きさ・fps・音声の形式をそろえる → `concat` → フェード（fade / afade）というフィルターグラフを作る。
  - 出力の大きさと fps は最初のクリップで決める。ほかのクリップは縦横比を保って合わせ、余りは黒い余白。音のないクリップは無音。
  - 長い編集の分割・切り取りは、全体の時刻で区間を決め、区間ごとにグラフを作り直す（入力側で頭出しするので速い）。フェードの時刻は全体での時刻なので、途中から作るときは `setpts` で時刻をずらしてからフェードをかける。
  - 「最初の2分20秒だけ」のときは先に 139秒に切ってからフェードアウトを付ける（フェードアウトが切れてなくならないように）。
  - 出力名は `最初の動画の名前_edit_x.mp4`。画面の「使う範囲」は編集した行には使わない。
- プレビュー: 変換と同じ `build_graph` を小さい大きさ（640x360 に収まる大きさ）・粗い拡大縮小で使うので、切り貼りもフェードも変換結果と一致する。
  - 1コマ: ffmpeg で rgb24 の1コマを作り、PPM にして `tk.PhotoImage` に渡す（Pillow 不要）。別スレッドで作り、最新の要求だけ処理する。
  - 再生: 映像は ffmpeg から 15fps の rgb24 を標準出力で受け取る。音は 22.05kHz の WAV を一時フォルダに書き出して `winsound` で鳴らし、実時間に合わせて映像のコマを進める（遅れたコマは捨てる）。1回の再生は 300秒まで。
- 編集の窓: プレビュー、タイムライン（部分ごとに色分け・フェードの範囲・赤い線。クリック/ドラッグで移動）、再生/停止（スペース）、±1コマ（左右キー）・±1秒、切り貼りのボタン、部分の一覧、フェードの秒数、決定/取り消し。

## やっていないこと
- GPU（NVENC など）での変換、字幕の焼き込み、音量の調整、GIF として投稿する形式への変換、X への自動投稿。
- 編集: 部分ごとのフェード・つなぎ目のクロスフェード、文字入れ、画面の切り抜き、速度の変更、BGM の追加、編集内容の保存（アプリを閉じると消える）。
